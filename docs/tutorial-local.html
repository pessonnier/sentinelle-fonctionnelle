Guide de prise en main locale

Structurer des plans et cas de test dans l’application locale.

Ce tutoriel installe et lance l’interface web locale, crée plusieurs projets et plans de test, puis montre comment organiser les suites et dossiers et rédiger chaque cas en pas-à-pas, Given/When/Then, tableau d’exemples ou checklist. Il associe ensuite des saisies CSV ou Excel et prépare leur itération en série, en parallèle ou aléatoirement. L’ensemble est persisté dans SQLite.

Avant de commencer

État actuel du produit

À savoir : l’interface web FastAPI locale est disponible sur la boucle locale. Le serveur ne lance pas automatiquement le navigateur : ouvrir manuellement http://127.0.0.1:8000 après son démarrage.
Disponible Interface web multi-projet : création de projets et plans de test, puis de suites, sous-suites, dossiers et cas de test.
Disponible Renommage, déplacement, ordre et archivage récursif, avec identité stable et restauration après redémarrage.
Disponible Persistance SQLite locale, migration version 5, transactions, sonde de santé et documentation OpenAPI.

Étape 1

Préparer le poste

Utiliser un clone du dépôt et se placer dans sa racine, celle qui contient pyproject.toml.

  • Python 3.12 ou plus récent ;
  • PowerShell sous Windows, ou un shell POSIX sous Linux/macOS ;
  • droits d’écriture dans le répertoire choisi pour SQLite ;
  • accès au registre Python lors de la première installation des dépendances.

Vérifier Python

Windows

py -3 --version

Linux ou macOS

python3 --version

Résultat attendu : une version égale ou supérieure à Python 3.12.

Créer l’environnement et installer l’application

Windows PowerShell

py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --editable ".[test]"

Linux ou macOS

python3 -m venv .venv
./.venv/bin/python -m pip install --editable ".[test]"

Résultat attendu : FastAPI, Uvicorn, Jinja et l’application sont installés dans .venv, sans modifier le Python système.

Étape 2

Comprendre la configuration actuelle

Le serveur lit quatre variables d’environnement, que les options de serve peuvent remplacer. Aucun fichier YAML n’est encore lu : un tel fichier serait ignoré.

Paramètre Portée Valeur / rôle Sensible
SENTINELLE_FONCTIONNELLE_MODE / --mode Serveur local par défaut. online est refusé tant que ses adaptateurs manquent. Non
SENTINELLE_FONCTIONNELLE_DATABASE / --database Persistance locale data/sentinelle_fonctionnelle.db, relatif à la racine de lancement. Non
SENTINELLE_FONCTIONNELLE_HOST / --host Serveur local 127.0.0.1. Ne pas utiliser 0.0.0.0 pour ce prototype. Non
SENTINELLE_FONCTIONNELLE_PORT / --port Serveur local 8000, entier compris entre 1 et 65535. Non
Ne placer aucun mot de passe ou jeton dans la ligne de commande ou dans SQLite. Aucun secret n’est nécessaire pour ce tutoriel.

Étape 3

Lancer l’application web locale

Exécuter la commande depuis la racine du dépôt. Le répertoire data et la base sont créés automatiquement.

Windows PowerShell

.\.venv\Scripts\python.exe -m sentinelle_fonctionnelle.cli serve `
  --database ".\data\sentinelle_fonctionnelle.db" `
  --host 127.0.0.1 `
  --port 8000

Linux ou macOS

./.venv/bin/python -m sentinelle_fonctionnelle.cli serve \
  --database "./data/sentinelle_fonctionnelle.db" \
  --host 127.0.0.1 \
  --port 8000

Résultat attendu : Uvicorn annonce http://127.0.0.1:8000. Cette adresse affiche la liste des projets ; /health répond {"status":"ok","mode":"local","schema_version":5}.

Arrêter et nettoyer

Revenir au terminal et presser Ctrl+C. Conserver data/sentinelle_fonctionnelle.db pour retrouver les projets au prochain lancement. Pour repartir à zéro, arrêter d’abord le serveur, sauvegarder si nécessaire, puis supprimer explicitement ce seul fichier.

Étape 4

Utiliser les fonctionnalités implémentées

Scénario 01

Créer deux projets depuis le navigateur

Objectif : vérifier le fonctionnement multi-projet et sa persistance locale.

  1. lancer le serveur avec la commande de l’étape 3 ;
  2. ouvrir http://127.0.0.1:8000 ;
  3. renseigner nom, description, cible web et politique, puis choisir Créer le projet ;
  4. revenir à Projets et répéter l’opération ;
  5. arrêter puis relancer le serveur avec le même fichier SQLite.

Les deux cartes de projet réapparaissent avec les mêmes données.

Traçabilité : EF-001 · EF-001.2 · EF-002 · ENF-013 · ACC-060 · ACC-061

Scénario 02

Construire et réorganiser une arborescence

Objectif : créer un plan, une suite, un dossier et un cas de test, puis exercer les opérations persistantes.

  1. ouvrir un projet, compléter le formulaire du plan « Parcours critiques », puis ouvrir ce plan ;
  2. ajouter une suite à la racine, puis un dossier en choisissant la suite comme parent ;
  3. ajouter un cas de test sous le dossier ; la racine du plan n’est pas proposée comme parent d’un cas ;
  4. renommer le cas, choisir un nouveau parent et une position, puis cliquer Déplacer ;
  5. archiver un conteneur, puis afficher les archivés.

Le même identifiant reste visible ; le conteneur et ses descendants portent l’état « Archivé » après redémarrage.

Traçabilité : EF-001.2 · EF-002 · EF-002.1 · ENF-013 · ACC-060 · ACC-062 · ACC-069 · ACC-070 · ACC-072

Scénario 03

Choisir une manière de spécifier le cas de test

Objectif : partir du vocabulaire le plus naturel pour l’équipe tout en obtenant la même définition structurée. Le cas et un plan « Parcours critiques » doivent déjà exister.

Mode À privilégier pour Forme attendue
Pas-à-pas un parcours linéaire dont chaque action a un résultat observable Action => Résultat, une paire par ligne
Given/When/Then partager une règle métier entre produit, recette et développement Étant donné…, Quand…, Alors…
Tableau d’exemples couvrir des combinaisons de données et des tables de décision en-têtes et lignes, avec colonnes séparées par ;
Checklist une revue visuelle, d’accessibilité ou de conformité un contrôle observable et indépendant par ligne
  1. ouvrir le cas depuis l’arbre du plan ;
  2. sélectionner le mode approprié avec le tableau ci-dessus ;
  3. renseigner le contexte, les étapes, les données facultatives et les résultats attendus ;
  4. ajouter si utile environnement, préconditions, données, postconditions, exigences, règles métier et déclaration d’exécution ;
  5. choisir Enregistrer le cas de test, puis modifier un champ et enregistrer de nouveau.

Le mode choisi et la version sont affichés. La seconde sauvegarde passe à la version 2 ; après redémarrage, le texte et toutes les métadonnées réapparaissent.

Traçabilité : EF-007 · EF-007.4 · ACC-063 · ACC-064 · ACC-071

Scénario 04

Organiser les mêmes cas selon le besoin de revue

Objectif : changer de point de vue sans déplacer ni dupliquer les cas. Plusieurs cas spécifiés avec des tags, exigences et règles métier différents sont nécessaires.

Trois structures d’arbre sont particulièrement utiles :

  • par domaine métier — « Clients / Réservations / Paiements » : stable et recommandée pour un produit durable ;
  • par parcours utilisateur — « Découvrir / Acheter / Annuler » : lisible pour une recette orientée expérience ;
  • par composant applicatif — « Portail / API / Back-office » : pratique quand les responsabilités techniques structurent les équipes.

La combinaison conseillée est un arbre stable domaine → parcours, des tags pour le risque, la campagne et le canal, puis les exigences et règles métier pour la traçabilité. Éviter un arbre par sprint ou par version : ces dimensions changent souvent et conviennent mieux aux tags.

Les vues disponibles complètent cet arbre :

  • Arbre : organisation de référence pour la navigation, le parent et l’ordre ;
  • Tags : campagnes transversales telles que smoke, paiement ou critique ;
  • Exigences : couverture et revue de traçabilité par identifiant ;
  • Règles métier : analyse d’impact lorsqu’une règle change ;
  • Modes de spécification : homogénéisation éditoriale et accompagnement des auteurs ;
  • Recherche : localisation ponctuelle par nom, tag, exigence ou contenu.
  1. choisir une valeur dans Vue d’organisation ;
  2. saisir éventuellement un mot dans Recherche ;
  3. cliquer Filtrer et ouvrir le cas recherché par son identifiant stable ;
  4. revenir à Arbre pour retrouver son parent et sa position d’origine.

Les groupes changent, mais l’identifiant du cas, son parent et son ordre restent identiques.

Traçabilité : EF-007.4 · ACC-065

Scénario 05

Associer des saisies CSV ou Excel à un cas de test

Objectif : transformer chaque ligne d’un tableau en cas de saisie et vérifier le plan qui sera transmis au futur runner. Un cas de test non archivé doit déjà exister.

Télécharger le modèle Excel prêt à remplir ou créer un CSV UTF-8 dont la première ligne contient les noms de variables : 

courriel;profil;montant
alice@example.invalid;standard;10.50
bob@example.invalid;premium;25.00
chloe@example.invalid;standard;0
Stratégie Plan produit Utilisation conseillée
Série un lot d’un cas par ligne, dans l’ordre du fichier parcours qui modifient un état partagé ou diagnostic simple
Parallèle lots limités par la concurrence choisie, de 1 à 20 cas indépendants sur une cible capable d’absorber la concurrence
Aléatoire échantillon sans doublon, ordre reproduit par la même graine varier l’ordre ou sélectionner un sous-ensemble reproductible
  1. ouvrir le cas, puis la section Fichier de données ;
  2. choisir le fichier et la stratégie d’itération ;
  3. pour Parallèle, fixer la concurrence maximale ;
  4. pour Aléatoire, fixer la graine et éventuellement le nombre de cas ;
  5. cliquer Analyser et associer les données ;
  6. contrôler les colonnes, l’empreinte, les lignes et le nombre de lots avant tout futur lancement.

Le fichier, sa version, les cas et le plan apparaissent. Après redémarrage, les mêmes valeurs et le même ordre aléatoire sont restaurés. Cet écran prépare le plan mais ne lance pas encore Playwright.

Traçabilité : EF-007.2 · EF-007.5 · ACC-066 · ACC-067 · ACC-068

Scénario 08

Persister et restaurer avec SQLite

Objectif : créer deux projets, déplacer un cas de test, fermer la composition puis restaurer les données.

Windows PowerShell

$database = ".\data\tutorial-$(Get-Date -Format yyyyMMdd-HHmmss).db"
.\.venv\Scripts\python.exe -m sentinelle_fonctionnelle.cli demo-persistence --database $database

Linux ou macOS

database="./data/tutorial-$(date +%Y%m%d-%H%M%S).db"
./.venv/bin/python -m sentinelle_fonctionnelle.cli demo-persistence --database "$database"

Observer "project_count": 2, "identity_preserved": true, "history_count": 1 et le chemin restauré.

Aide

Résoudre les problèmes fréquents

No module named sentinelle_fonctionnelle
Vérifier que le terminal se trouve à la racine du dépôt et rejouer l’installation éditable avec le Python de .venv.
unable to open database file
Vérifier les droits d’écriture sur le chemin demandé. Le serveur crée le répertoire parent, mais ne peut pas contourner les droits du système.
Le nombre de projets est supérieur à deux
La commande de démonstration ajoute des données à chaque exécution. Utiliser un nouveau nom de fichier SQLite pour obtenir le résultat initial du tutoriel.
address already in use
Un autre processus utilise le port. Relancer avec --port 8010, puis ouvrir http://127.0.0.1:8010.
Le CSV est refusé alors qu’il s’ouvre dans Excel
Réenregistrer le fichier en CSV UTF-8. Vérifier que la première ligne contient des en-têtes uniques et qu’au moins une ligne de données suit l’en-tête.
Le classeur XLSX contient une formule
Copier les résultats utiles puis les coller comme valeurs dans un nouveau classeur sans macro ni connexion. Les formules sont refusées afin que l’import ne dépende jamais d’un calcul actif.
Le mode online est refusé
C’est volontaire : l’authentification réelle et la persistance partagée ne sont pas disponibles. Utiliser local ; ne pas exposer ce prototype sur le réseau.

Périmètre honnête

Ce que ce tutoriel ne lance pas encore

  • un fournisseur LLM de conception ou d’exécution ;
  • la génération de code Playwright ;
  • le runner navigateur isolé ;
  • le lancement effectif des lots série, parallèles ou aléatoires préparés par l’import ;
  • PostgreSQL, l’authentification réelle et l’application partagée multi-utilisateur ;
  • l’historique consultable de toutes les versions et leur approbation immuable ;
  • la protection CSRF nécessaire avant toute exposition réseau ;
  • Docker, Podman et les modèles CI.

Ces éléments existent dans les spécifications mais restent planifiés. Ils seront ajoutés à ce guide uniquement après une preuve RED/GREEN et un point d’entrée réel vérifié.
